# A separate chapter for installed startup

The startup explanation has its own chapter so a reader can follow one
question: how does an installed service decide what it may serve before
opening a listener? The homepage retains its existing selected-work hierarchy.
Article 07 links to the new chapter without absorbing another long section.

The chapter starts with the operator's problem, introduces three input roles,
shows the accepted startup path and compares three configuration outcomes.
Exact declaration fields and path rules are linked to the pinned operator
guide. The source-tree model launcher and reader-device browser lab are
compared explicitly, because they do not share one runtime or startup scope.

The six-component Archify map pins fourteen source ranges to API revision
`b94c92f0fa4c98914e5a2907e5044a943bea134a`. The optional absent branch is dashed;
its label remains on the affected relationship. Failure behavior appears in
the caption, notes and configuration table. An unsupported layout may remain
an omission inside a valid snapshot. The Uvicorn listener is a backend
component; it is not a message queue.

| Before | After | Why |
| --- | --- | --- |
| Startup details would extend the already long execution chapter | One separate chapter with six section links | Readers can choose the installation question without losing the earlier narrative |
| Stock diagram typography is small when fitted to the page | Source labels 22px, supporting text 20px and edge labels 18px | Actual 1280-width IAB review measured about 17.6px, 16px and 14.4px in the initial view |
| A dense failure fan-out would compete with the accepted sequence | Numbered accepted path, one optional branch and a three-row outcome table | Readers can understand the normal path and distinguish omitted configuration from invalid configuration |

The installed Archify CLI was actually used for initial delivery and strict
provenance checking. A task-local copy of the established readable renderer
generated the committed LIGHT artifact; the installed skill was not edited.
Its final stock check passes all nine checks with no composition errors or
warnings. Real browser work uses the Codex in-app browser exclusively; the
stock external-browser finalizer was not run. Browser rendering, source-link
interaction and PNG/LIGHT-SVG download events were inspected separately.

The local article was measured at requested widths 320, 390, 1280 and 1920.
Body text is 18px on the two narrow widths and 19px on the desktop widths.
The page has no horizontal overflow; comparison tables keep their own
horizontal scrolling on narrow screens. The surrounding journal remains DARK
and the embedded figure is explicitly LIGHT. These measurements do not
establish physical-phone or screen-reader acceptance.

Official research used the PyPA executable-script guide and Anyscale's
production RAG guide in the Codex browser. The course mapping was checked
against the CS310 web-services and CS381 layering originals. The learner
exercise is proposed work, not a claim that it was completed.

Source/build checks, publication identity, native model execution and
financial adjudication remain distinct evidence. The new chapter accurately
describes the already audited installed API-only startup boundary; it does
not introduce a new model run, financial accuracy denominator or hosted API.
