## Consumer setup

The accepted CI toolchain is Python 3.13 and Node.js 24. API metadata permitting Python `>=3.11` is a separate compatibility declaration; that metadata does not establish a Python 3.11 CI run. From the repository root:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
npm ci --prefix browser-rag
python scripts/materialize-browser-assets.py
python build.py --public
python -m http.server 8765 --directory dist --bind 127.0.0.1
```

Open `http://127.0.0.1:8765/`. These are the clean-checkout commands used by the public-build profile. The materializer downloads exact fixed-revision model/card bytes into ignored `browser-rag/.model-cache/`, verifies their sizes and SHA-256 values, and refuses mismatches. Model weights are not Git blobs. `npm ci` preserves the lockfile's runtime versions; model/runtime revisions are not chosen from an unpinned latest alias.

For the ordinary inspector profile, materialize only MiniLM and omit the public switch:

```powershell

```

## Reader contract and asset budget

The reader chooses a local PDF and starts each model action explicitly. PDF parsing and source-cell lookup use that accepted local source. Passage/query embeddings and native generation run on the reader's device with the supported WebGPU profile. State the selected-PDF upload behavior and the first-run download separately: browser computation is local; inference assets use logical site URLs and the owned verified cache. The explicit preparation-only option below can fetch model bodies from Hugging Face. No blanket all-network, universal offline, every-device or financial-accuracy claim follows from this architecture.

The explicit preparation worker verifies static files without receiving a PDF, question or context or invoking a model/GPU. Its fixed 30-minute absolute budget includes a 10-second readiness limit and is not renewed by progress. A complete receipt covers eight pinned bodies and successful cache writes. Later model actions verify the cache again and retain their original 120-second encoder/query and 300-second generator limits. Cache eviction or a missing body can still affect a later action. Preparation has its own static receipt; model loading is a named phase inside the native operation receipt, and inference requires its own runtime evidence.

The preparation protocol deployed at historical `7c7a2c3` was v2: site remains the default, with an explicit Hugging Face choice and no automatic fallback. Decoded size/EOF/SHA gates, logical site cache keys and remote-model SDK restrictions remain unchanged. The [official download reference](https://huggingface.co/docs/huggingface_hub/v2.2.0/en/package_reference/file_download#huggingface_hub.hf_hub_url) supports immutable revision URLs; the [Xet migration description](https://huggingface.co/blog/migrating-the-hub-to-xet) describes its bridge delivery.
